# 3.6 Multi‑Agent Systems: Orchestrating Specialized AI Collaborators

Multi-agent systems allow multiple specialized agents to collaborate on complex tasks. In LangGraph:

- Each agent is a **node**
- Agents communicate through a **shared state**
- A **supervisor agent** decides who acts next

---

# Why Multi‑Agent Systems?

- **Specialization**: Each agent has its own prompt, tools, or model.
- **Scalability**: Add or replace agents without rewriting the system.
- **Robustness**: Supervisor can reroute if an agent fails.
- **Modularity**: Easier testing and maintenance.

---

# 1. Multiple Agents as Separate Nodes

Each agent node:

- Reads relevant parts of the state
- Performs its logic (LLM calls, tools)
- Updates the state

### Example: Researcher and Writer

```python
from typing import TypedDict, List, Annotated
import operator
from langgraph.graph import StateGraph, END
from langchain.chat_models import ChatOpenAI
from langchain.prompts import ChatPromptTemplate

class AgentState(TypedDict):
    task: str
    research_notes: Annotated[List[str], operator.add]
    draft: str
    final_output: str
    next: str

def researcher(state: AgentState) -> dict:
    llm = ChatOpenAI(model="gpt-3.5-turbo")
    prompt = ChatPromptTemplate.from_template(
        "You are a researcher. Gather information about: {task}\nProvide concise notes."
    )
    chain = prompt | llm
    result = chain.invoke({"task": state["task"]})
    return {"research_notes": [result.content]}

def writer(state: AgentState) -> dict:
    llm = ChatOpenAI(model="gpt-3.5-turbo")
    notes = "\n".join(state["research_notes"])
    prompt = ChatPromptTemplate.from_template(
        "You are a writer. Based on these notes, write a clear article:\n{notes}"
    )
    chain = prompt | llm
    result = chain.invoke({"notes": notes})
    return {"draft": result.content}
```

# 2. Shared State – Agent Communication

- Central communication bus
- Agents read/write state
- Use reducers to control updates:

| Reducer         | Behavior                                   |
| --------------- | ------------------------------------------ |
| `operator.add`  | Append to lists (accumulate contributions) |
| None            | Last write wins (careful)                  |
| Custom reducers | Merge dicts, complex types                 |

# 3. Supervisor Agent – Coordinates Agents

A node that reads the current state and decides the next agent(s).

### Simple supervisor

```python
def supervisor(state: AgentState) -> dict:
    if not state.get("research_notes"):
        return {"next": "researcher"}
    elif not state.get("draft"):
        return {"next": "writer"}
    else:
        return {"next": "END"}
```

### LLM-based supervisor

```python
def llm_supervisor(state: AgentState) -> dict:
    prompt = ChatPromptTemplate.from_template(
        "You are a coordinator. Current task: {task}\n"
        "Notes: {notes}\nDraft: {draft}\nWho acts next? Options: researcher, writer, or FINISH."
    )
    chain = prompt | ChatOpenAI(model="gpt-3.5-turbo") | str
    decision = chain.invoke({
        "task": state["task"],
        "notes": state.get("research_notes", []),
        "draft": state.get("draft", "")
    })
    return {"next": "END" if decision.strip().lower() == "finish" else decision.strip().lower()}
```

# Complete Example: Research‑Then‑Write with Supervisor

```python
import operator
from typing import TypedDict, List, Annotated
from langgraph.graph import StateGraph, END

class AgentState(TypedDict):
    task: str
    research_notes: Annotated[List[str], operator.add]
    draft: str
    iterations: int
    next: str

# Nodes
def researcher(state: AgentState) -> dict:
    # Simulate LLM research
    return {"research_notes": [f"Notes for {state['task']}"], "iterations": state.get("iterations", 0) + 1}

def writer(state: AgentState) -> dict:
    draft = "\n".join(state["research_notes"])
    return {"draft": draft}

def supervisor(state: AgentState) -> dict:
    if state.get("iterations", 0) > 3:
        return {"next": "END"}
    if not state.get("research_notes"):
        return {"next": "researcher"}
    if not state.get("draft"):
        return {"next": "writer"}
    return {"next": "END"}

def route_next(state: AgentState) -> str:
    return state["next"]

# Build graph
builder = StateGraph(AgentState)
builder.add_node("supervisor", supervisor)
builder.add_node("researcher", researcher)
builder.add_node("writer", writer)

builder.set_entry_point("supervisor")
builder.add_conditional_edges("supervisor", route_next)
builder.add_edge("researcher", "supervisor")
builder.add_edge("writer", "supervisor")

app = builder.compile()

# Run
initial_state = {"task": "Explain benefits of multi-agent systems", "research_notes": [], "iterations": 0}
result = app.invoke(initial_state)
print("Draft:", result["draft"])
print("Research notes:", result["research_notes"])
```

# Parallel Agents

- Conditional edges can return a **list of nodes** for concurrent execution.
- Updates are merged using reducers.
- Example:

```python
def parallel_supervisor(state: AgentState) -> dict:
    return {"next": ["search_web", "query_database"]}

builder.add_conditional_edges("supervisor", lambda s: s["next"])
```

# Where to Use Multi-Agent Systems

| Scenario           | Agents Needed                                |
| ------------------ | -------------------------------------------- |
| Content creation   | Researcher, writer, editor, fact-checker     |
| Customer support   | Intent classifier, knowledge base agent      |
| Code generation    | Analyst, coder, tester, reviewer             |
| Research assistant | Web searcher, summarizer, citation formatter |
| Data analysis      | Fetcher, analyst, report writer              |
| Game AI            | Player agent, referee, commentator           |

---

# Summary

- **Agents as nodes**: Each node specializes in a task.
- **Shared state**: Communication channel between agents.
- **Supervisor**: Determines next agent(s) using conditional edges.
- **Parallel execution**: Run multiple agents concurrently, merge updates.
- **Iteration control**: Counters or flags prevent infinite loops.

Multi-agent systems let you decompose complex AI workflows into specialized, reusable components with clear coordination and shared knowledge.
