# 3.2 Nodes & Edges: Building the Graph Topology

In LangGraph, workflows are defined as **state graphs**.

A graph consists of:

- **Nodes** → Perform computation
- **Edges** → Control execution flow
- **Entry point** → Defines where execution starts

Mastering nodes and edges allows you to build:

- Cyclic workflows
- Branching logic
- Parallel execution
- Agent-style reasoning loops

---

# 1. Node Functions – The Workhorses

A node is any callable that:

- Receives the full current state
- Returns a partial state update (dict)
- The graph merges updates using reducers (if defined)

---

## Basic Node Structure

```python
def my_node(state: dict) -> dict:
    query = state["query"]
    result = f"Processed: {query}"
    return {
        "processed_result": result,
        "steps": ["my_node"]
    }
```

### Key Rules

- Input = entire state
- Output = only updated keys
- Non-returned keys remain unchanged
- Reducers determine merge behavior

---

## Async Nodes

If your node performs I/O (API calls, DB queries), use async:

```python
import aiohttp

async def fetch_data(state: dict) -> dict:
    async with aiohttp.ClientSession() as session:
        async with session.get(
            f"https://api.example.com/{state['id']}"
        ) as resp:
            data = await resp.json()
    return {"api_data": data}
```

### Running Async Graphs

- `graph.invoke()` → Sync graphs
- `graph.ainvoke()` → Async or mixed graphs

---

## Nodes Returning None

If no state update is needed:

```python
def log_step(state: dict) -> None:
    print(f"Steps so far: {state.get('steps')}")
```

Useful for:

- Logging
- Metrics
- Notifications
- Pure side effects

---

## Common Node Use Cases

- LLM calls
- Retrieval operations
- Tool execution
- Planning logic
- State transformations
- Error handling
- Logging

---

# 2. Normal Edges – Unconditional Flow

A normal edge defines a fixed transition.

```python
from langgraph.graph import StateGraph

builder = StateGraph(GraphState)

builder.add_node("node_a", node_a_function)
builder.add_node("node_b", node_b_function)

builder.add_edge("node_a", "node_b")
```

Meaning:
After `node_a` finishes → always execute `node_b`.

---

## When to Use Normal Edges

- Linear pipelines
- Preprocessing steps
- Post-processing
- Cleanup steps
- Deterministic workflows

---

# 3. Conditional Edges – Dynamic Routing

Conditional edges allow state-based branching.

You define:

- A routing function
- Optional mapping dictionary

---

## Basic Conditional Edge

```python
def route(state: dict) -> str:
    if state.get("answer"):
        return "end"
    else:
        return "retry_node"

builder.add_conditional_edges(
    "check_node",
    route,
    {
        "end": "final_node",
        "retry_node": "retrieve_again"
    }
)
```

Routing function returns a string.
Mapping connects returned string to actual node.

---

## Direct Routing (No Mapping)

```python
def route_direct(state: dict) -> str:
    return "node_b" if state["valid"] else "node_c"

builder.add_conditional_edges("node_a", route_direct)
```

Returned string must match node name.

---

## Parallel Routing

Return a list of nodes:

```python
def route_parallel(state: dict) -> list:
    return ["search_web", "query_database"]

builder.add_conditional_edges("planner", route_parallel)
```

Both nodes execute in parallel.

Reducers merge their outputs.

---

## When to Use Conditional Edges

- Agent decision making
- Retry loops
- Tool selection
- Error recovery
- Adaptive workflows
- Parallel processing

---

# 4. Entry Point – Starting the Graph

Every graph needs one entry point.

```python
builder.set_entry_point("retrieve_node")
```

Execution always begins here.

If you need multiple starting paths:

- Create a dummy start node
- Route using conditional edges

---

# Complete Example: Conditional QA Agent

This graph:

1. Retrieve documents
2. Generate answer
3. Check answer quality
4. Retry retrieval if needed (max 2 times)
5. Format final answer

---

## Full Implementation

```python
from typing import TypedDict, List, Annotated
import operator
from langgraph.graph import StateGraph, END

class GraphState(TypedDict):
    query: str
    retrieved_docs: Annotated[List[str], operator.add]
    answer: str
    attempts: int
    steps: Annotated[List[str], operator.add]

# Nodes
def retrieve(state: GraphState) -> dict:
    query = state["query"]
    docs = [f"Doc about {query} (attempt {state.get('attempts', 0)+1})"]
    return {
        "retrieved_docs": docs,
        "steps": ["retrieve"],
        "attempts": state.get("attempts", 0) + 1
    }

def generate(state: GraphState) -> dict:
    docs = state.get("retrieved_docs", [])
    answer = f"Based on: {docs[-1]}"
    return {
        "answer": answer,
        "steps": ["generate"]
    }

def check(state: GraphState) -> dict:
    answer = state.get("answer", "")
    if len(answer) < 20 and state.get("attempts", 0) < 2:
        return {"steps": ["check: need more docs"]}
    else:
        return {"steps": ["check: answer ok"]}

def format_answer(state: GraphState) -> dict:
    return {
        "answer": f"Final: {state['answer']}",
        "steps": ["format"]
    }

# Routing
def route_after_check(state: GraphState) -> str:
    if "check: need more docs" in state["steps"]:
        return "retrieve"
    else:
        return "format"

# Build graph
builder = StateGraph(GraphState)

builder.add_node("retrieve", retrieve)
builder.add_node("generate", generate)
builder.add_node("check", check)
builder.add_node("format", format_answer)

builder.set_entry_point("retrieve")

builder.add_edge("retrieve", "generate")
builder.add_edge("generate", "check")

builder.add_conditional_edges(
    "check",
    route_after_check,
    {
        "retrieve": "retrieve",
        "format": "format"
    }
)

builder.add_edge("format", END)

graph = builder.compile()

# Run
initial = {"query": "LangGraph", "attempts": 0}
result = graph.invoke(initial)

print("Final answer:", result["answer"])
print("Steps:", result["steps"])
```

---

# Execution Flow Explanation

- `retrieve` increments attempts
- `generate` produces answer
- `check` determines if retry is needed
- `route_after_check` decides next step
- Graph may loop up to 2 times
- `format` finalizes answer
- Graph ends at `END`

---

# Mental Model

Think of:

Nodes = Functions
Edges = Flow Control
State = Shared Memory

LangGraph = Directed State Machine

---

# Concept Summary

| Concept           | Purpose                       |
| ----------------- | ----------------------------- |
| Node functions    | Perform work and update state |
| Normal edges      | Fixed transitions             |
| Conditional edges | Dynamic routing               |
| Parallel routing  | Concurrent execution          |
| Entry point       | Graph starting node           |

---

# Key Takeaways

- Nodes are pure functions over state.
- Nodes return partial updates.
- Edges define execution order.
- Conditional edges enable dynamic logic.
- Parallel execution is supported.
- Entry point is mandatory.

With nodes and edges, you can build:

- Agents
- Retry systems
- Multi-step reasoning workflows
- Tool-using systems
- Complex adaptive pipelines

This is the foundation of LangGraph topology.
