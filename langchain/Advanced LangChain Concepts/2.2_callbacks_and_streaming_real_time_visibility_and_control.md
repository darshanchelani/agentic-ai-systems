# 2.2 Callbacks & Streaming: Real-Time Visibility and Control

## 📌 Overview

In production LLM systems, you need:

- 🔍 Observability
- 📊 Monitoring
- ⚡ Real-time output
- 🛑 Error tracking
- 💰 Cost visibility

Two core mechanisms provide this:

1. **Callbacks** → Hooks into lifecycle events
2. **Streaming** → Token-by-token output

Together, they transform your system from a black box into a transparent, interactive pipeline.

---

# 🧠 Big Picture Mental Model

```
User Request
    ↓
Prompt → LLM → Tool → Chain
    ↓
Callbacks observe every step
    ↓
Streaming returns tokens live
```

Callbacks = Visibility
Streaming = Responsiveness

---

# 1️⃣ Callback Handlers

Callbacks are functions triggered at specific lifecycle events:

- LLM start/end
- Chain start/end
- Tool execution
- Retriever calls
- Token generation
- Errors

They allow you to:

- Log
- Trace
- Monitor
- Trigger side effects
- Track cost & latency

---

# 🎯 Why Use Callbacks?

- ✅ Debugging
- ✅ Observability
- ✅ Cost tracking
- ✅ Custom dashboards
- ✅ Error monitoring
- ✅ Logging to databases
- ✅ Sending notifications

# 🔹 Core Callback Events

You can hook into:

### LLM Events

- `on_llm_start`
- `on_llm_end`
- `on_llm_error`
- `on_llm_new_token` (streaming)

### Chain Events

- `on_chain_start`
- `on_chain_end`
- `on_chain_error`

### Tool Events

- `on_tool_start`
- `on_tool_end`
- `on_tool_error`

### Retriever Events

- `on_retriever_start`
- `on_retriever_end`
- `on_retriever_error`

# 2️⃣ Creating a Custom Callback Handler

Subclass `BaseCallbackHandler`.

```python
from langchain.callbacks.base import BaseCallbackHandler
from langchain.schema import LLMResult
import time

class LoggingCallbackHandler(BaseCallbackHandler):
    def __init__(self, log_file="trace.log"):
        self.log_file = log_file

    def _log(self, message: str):
        with open(self.log_file, "a") as f:
            f.write(f"{time.strftime('%Y-%m-%d %H:%M:%S')} - {message}\n")

    def on_llm_start(self, serialized: dict, prompts: list, **kwargs):
        self._log(f"LLM Start: {prompts}")

    def on_llm_end(self, response: LLMResult, **kwargs):
        self._log(f"LLM End: {response.generations}")

    def on_chain_start(self, serialized: dict, inputs: dict, **kwargs):
        self._log(f"Chain Start: {inputs}")

    def on_chain_end(self, outputs: dict, **kwargs):
        self._log(f"Chain End: {outputs}")

    def on_tool_start(self, serialized: dict, input_str: str, **kwargs):
        self._log(f"Tool Start: {serialized.get('name')} | {input_str}")

    def on_tool_end(self, output: str, **kwargs):
        self._log(f"Tool End: {output}")
```

# 🔹 Using Callbacks

You attach handlers via:

```python
config={"callbacks": [handler]}
```

---

## Example: LLM with Callback

```python
from langchain.chat_models import ChatOpenAI

logger = LoggingCallbackHandler()
llm = ChatOpenAI(model="gpt-3.5-turbo")

llm.invoke("Hello", config={"callbacks": [logger]})
```

---

## Example: LCEL Chain with Callback

```python
from langchain.prompts import ChatPromptTemplate

prompt = ChatPromptTemplate.from_template(
    "Tell me a joke about {topic}"
)

chain = prompt | llm

chain.invoke(
    {"topic": "programmers"},
    config={"callbacks": [logger]}
)
```

---

## Example: Agent with Callback

```python
from langchain.tools import tool
from langchain.agents import create_openai_tools_agent, AgentExecutor

@tool
def get_length(s: str) -> int:
    return len(s)

tools = [get_length]

agent = create_openai_tools_agent(llm, tools, prompt)
executor = AgentExecutor(agent=agent, tools=tools)

executor.invoke(
    {"input": "Length of 'hello'?"},
    config={"callbacks": [logger]}
)
```

---

# 🔎 Inheritance Behavior

If you attach callbacks at the root level:

```
chain.invoke(..., config={"callbacks": [handler]})
```

They propagate to:

- All LLM calls
- All tools
- All retrievers

Provided `inheritable=True` (default).

# 4️⃣ Streaming Tokens – Real-Time Output

Streaming sends output **token-by-token** instead of waiting for completion.

Essential for:

- Chatbots
- Long responses
- UI responsiveness
- Streaming APIs

---

## 🔹 Streaming from Models

```python
from langchain.chat_models import ChatOpenAI

llm = ChatOpenAI(
    model="gpt-3.5-turbo",
    streaming=True
)

for chunk in llm.stream("Tell me a long story"):
    print(chunk.content, end="", flush=True)
```

Each `chunk` is an `AIMessageChunk`.

---

# 5️⃣ Streaming with LCEL Chains

If all components support streaming → chain streams automatically.

```python
prompt = ChatPromptTemplate.from_template(
    "Write a poem about {subject}"
)

llm = ChatOpenAI(
    model="gpt-3.5-turbo",
    streaming=True
)

chain = prompt | llm | (lambda msg: msg.content)

for chunk in chain.stream({"subject": "the ocean"}):
    print(chunk, end="", flush=True)
```

---

## 🔎 What Is Streamable?

| Component            | Streamable? |
| -------------------- | ----------- |
| Chat Models          | ✅ Yes      |
| Prompts              | ✅ Yes      |
| StrOutputParser      | ✅ Yes      |
| PydanticOutputParser | ❌ No       |
| Retrievers           | ❌ No       |

# 6️⃣ Streaming Agents

Agents stream intermediate reasoning + final output.

```python
for chunk in executor.stream({
    "input": "Search for AI news then tell a joke"
}):
    print(chunk)
```

Possible chunk keys:

- `output`
- `actions`
- `messages`
- `steps`

You can inspect type and route accordingly.

# 7️⃣ Async Streaming

For async apps (FastAPI, WebSockets):

```python
async for chunk in chain.astream(
    {"subject": "the ocean"}
):
    print(chunk, end="", flush=True)
```

Use:

- `.ainvoke()`
- `.astream()`

# 8️⃣ Async Callbacks – Non-Blocking Logging

When using async pipelines, sync callbacks can block execution.

Use `AsyncCallbackHandler`.

---

## 🔹 Creating Async Handler

```python
from langchain.callbacks.base import AsyncCallbackHandler

class AsyncDatabaseLogger(AsyncCallbackHandler):

    async def on_llm_start(self, serialized, prompts, **kwargs):
        await some_async_db.insert({
            "event": "llm_start",
            "prompts": prompts
        })

    async def on_llm_end(self, response, **kwargs):
        await some_async_db.insert({
            "event": "llm_end",
            "generations": response.generations
        })
```

---

## 🔹 Using Async Handler

```python
async def main():
    llm = ChatOpenAI(model="gpt-3.5-turbo")
    handler = AsyncDatabaseLogger()

    await llm.ainvoke(
        "Hello",
        config={"callbacks": [handler]}
    )
```

---

# ⚠️ Important Warning

If using `.ainvoke()` and your callback is synchronous:

→ It will block the event loop.

Always use async handlers for I/O operations.

---

# 9️⃣ Streaming + Async Logging Example (FastAPI)

```python
from fastapi import FastAPI
from fastapi.responses import StreamingResponse
from langchain.callbacks import AsyncCallbackHandler

app = FastAPI()

class StreamLogger(AsyncCallbackHandler):
    async def on_llm_new_token(self, token: str, **kwargs):
        print(f"Token: {token}", flush=True)

@app.get("/joke")
async def joke(topic: str):

    handler = StreamLogger()

    async def generate():
        async for chunk in chain.astream(
            {"topic": topic},
            config={"callbacks": [handler]}
        ):
            yield chunk

    return StreamingResponse(
        generate(),
        media_type="text/plain"
    )
```

# 🏁 Key Takeaways

- Callbacks provide deep observability.
- Attach via `config={"callbacks": [...]}`.
- Use streaming for responsive UX.
- LCEL chains stream automatically if components support it.
- Agents stream intermediate steps.
- Use async callbacks in async contexts.
- Avoid blocking the event loop.
- Combine streaming + async logging for production-grade systems.
