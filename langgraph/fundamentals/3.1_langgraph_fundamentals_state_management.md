# 3. LangGraph Fundamentals: State Management

LangGraph extends LangChain by introducing **stateful, cyclic graphs**.

Unlike traditional LangChain chains (which are linear and mostly stateless), LangGraph allows:

- Shared mutable state
- Cycles (loops)
- Conditional branching
- Parallel execution

State management is the **core foundation** of LangGraph. Understanding it properly is critical for building agents, multi-step workflows, and adaptive systems.

---

# 3.1 State Schema – Defining the Graph Memory

The **state** is the central shared data structure of your graph.

Each node:

- Reads from the state
- Returns partial updates to the state
- Does NOT overwrite the entire state (unless specified)

---

## Why Define a Schema?

- ✅ Type safety
- ✅ Clear documentation of what your graph tracks
- ✅ Enables reducers for safe state updates
- ✅ Better debugging and maintainability

---

## Option 1: Using `TypedDict` (Lightweight)

Best for:

- Quick prototyping
- When validation is not required

```python
from typing import TypedDict, List

class GraphState(TypedDict):
    query: str
    retrieved_docs: List[str]
    answer: str
    steps: List[str]
```

Characteristics:

- No runtime validation
- Fast and simple
- Good for smaller projects

---

## Option 2: Using Pydantic (Validation + Defaults)

Best for:

- Production systems
- Complex nested structures
- When you want validation

```python
from pydantic import BaseModel, Field
from typing import List, Optional

class GraphState(BaseModel):
    query: str
    retrieved_docs: List[str] = Field(default_factory=list)
    answer: Optional[str] = None
    steps: List[str] = Field(default_factory=list)
```

Advantages:

- Automatic validation
- Default values
- Better structure for complex agents

---

## Passing State to LangGraph

```python
from langgraph.graph import StateGraph

graph = StateGraph(GraphState)
```

---

# 3.2 Reducers – Controlling How State Updates Combine

In graphs:

- Multiple nodes may update the same key
- Nodes may run in parallel
- Cycles may repeatedly update state

Reducers define **how updates merge** instead of overwrite.

---

## Default Behavior (No Reducer)

If no reducer is defined:

- The last write wins
- Parallel writes are non-deterministic

⚠️ Dangerous in concurrent graphs.

---

## Built-in Reducer: `operator.add`

Commonly used for:

- Lists (append behavior)
- Numbers (addition)

```python
from typing import TypedDict, List, Annotated
import operator

class GraphState(TypedDict):
    query: str
    retrieved_docs: List[str]  # overwritten
    steps: Annotated[List[str], operator.add]  # appended
```

Now:

- Returning `{"steps": ["step1"]}`
- Then returning `{"steps": ["step2"]}`

Final result:

```python
["step1", "step2"]
```

---

## Custom Reducer Example

```python
def merge_dicts(current: dict, new: dict) -> dict:
    return {**current, **new}

class GraphState(TypedDict):
    metadata: Annotated[dict, merge_dicts]
```

Custom reducers are useful for:

- Merging dictionaries
- Deduplicating lists
- Maintaining sorted values
- Custom conflict resolution logic

---

## Why Reducers Are Essential

| Scenario                | Why Reducer Matters         |
| ----------------------- | --------------------------- |
| Parallel nodes          | Prevent race conditions     |
| Cycles                  | Accumulate results safely   |
| Multi-retriever systems | Combine retrieved documents |
| Logging                 | Append execution steps      |

---

# 3.3 State Keys – Reading and Writing from Nodes

Nodes:

- Receive full state
- Return partial updates
- Only modify keys they return

---

## Basic Node Structure

```python
def node_function(state: GraphState) -> dict:
    query = state["query"]
    result = some_llm_call(query)
    return {
        "answer": result,
        "steps": ["called node_function"]
    }
```

Important:

- State is read-only inside the function
- You return a dict with updates
- Reducers handle merging

---

## Retrieval Node Example

```python
def retrieve_docs(state: GraphState) -> dict:
    query = state["query"]
    docs = [f"doc about {query}", f"another doc"]
    return {
        "retrieved_docs": docs,
        "steps": ["retrieved"]
    }
```

---

## Conditional Edge Example

Conditional edges inspect state and decide next node.

```python
def has_answer(state: GraphState) -> str:
    if state.get("answer"):
        return "end"
    else:
        return "continue_processing"
```

# Complete Example: Retrieval → Generate → Check Loop

This graph:

1. Retrieves documents
2. Generates answer
3. Checks answer
4. Loops if necessary

---

## Full Implementation

```python
from typing import TypedDict, List, Annotated
import operator
from langgraph.graph import StateGraph, END

class GraphState(TypedDict):
    query: str
    retrieved_docs: Annotated[List[str], operator.add]
    answer: str
    steps: Annotated[List[str], operator.add]

# Nodes
def retrieve(state: GraphState) -> dict:
    query = state["query"]
    docs = [f"Document about {query}"]
    return {"retrieved_docs": docs, "steps": ["retrieve"]}

def generate(state: GraphState) -> dict:
    docs = state.get("retrieved_docs", [])
    answer = f"Based on docs: {docs}"
    return {"answer": answer, "steps": ["generate"]}

def check_answer(state: GraphState) -> dict:
    answer = state.get("answer", "")
    if len(answer) < 20 and len(state.get("retrieved_docs", [])) < 3:
        return {"steps": ["check: need more docs"]}
    else:
        return {"steps": ["check: answer ok"]}

# Conditional routing
def after_check(state: GraphState) -> str:
    if "check: need more docs" in state["steps"]:
        return "retrieve"
    else:
        return END

# Build graph
builder = StateGraph(GraphState)
builder.add_node("retrieve", retrieve)
builder.add_node("generate", generate)
builder.add_node("check", check_answer)

builder.set_entry_point("retrieve")
builder.add_edge("retrieve", "generate")
builder.add_edge("generate", "check")
builder.add_conditional_edges("check", after_check)

graph = builder.compile()

# Run
initial_state = {"query": "What is LangGraph?"}
result = graph.invoke(initial_state)
print(result)
```

---

# Mental Model of LangGraph State

Think of LangGraph state like:

> A shared memory object that flows through nodes, gets updated incrementally, and persists across loops.

Each node:

- Reads what it needs
- Writes what it changes
- Reducers define how changes combine

---

# When to Use Each Concept

| Concept           | Use Case                                 |
| ----------------- | ---------------------------------------- |
| State Schema      | Define memory of complex agents          |
| Reducers          | Multi-path workflows, parallel execution |
| Conditional Edges | Adaptive reasoning systems               |
| Cycles            | Iterative refinement, retry logic        |

---

# Key Takeaways

- State is the backbone of LangGraph.
- Use `TypedDict` for simple systems.
- Use Pydantic for production-grade validation.
- Reducers prevent state corruption.
- Nodes return partial updates only.
- Keys without reducers are overwritten.
- Reducers merge updates deterministically.

---

State management enables:
