# 2.4 Caching & Rate Limiting: Production-Ready Resilience and Cost Control

## 📌 Overview

When moving from prototype → production, two major concerns arise:

- 💰 **Cost control**
- 🛡️ **Reliability & resilience**

LLM APIs:

- Charge per token
- Enforce rate limits
- Can return transient errors (429, timeouts, etc.)

To build production-ready systems, you need:

1. **Caching** → avoid redundant API calls
2. **Rate limiting & retries** → survive throttling
3. **Cost tracking** → monitor and optimize usage

---

# 🧠 Production Mental Model

```
User Request
     ↓
Cache Check
     ↓ (miss)
LLM Call (with retry + backoff)
     ↓
Cost Tracking
     ↓
Store in Cache
     ↓
Return Response
```

---

# 1️⃣ LLM Caching

Caching stores LLM responses for identical inputs.

If the same prompt is called again:

- ❌ No API call
- 💰 No cost
- ⚡ Instant response

---

## 🎯 Why Cache?

- Reduce API cost
- Reduce latency
- Improve determinism (great for testing)
- Handle repeated queries (FAQs, analytics)

---

## 📦 Available Cache Types

| Cache           | Description            | Best For                    |
| --------------- | ---------------------- | --------------------------- |
| `InMemoryCache` | Python dictionary      | Dev/testing, single process |
| `RedisCache`    | External Redis server  | Distributed systems         |
| `SQLiteCache`   | Local persistent DB    | Single machine production   |
| `MomentoCache`  | Serverless cloud cache | Cloud-native/serverless     |

---

## 🔹 Enable Global Caching

```python
import langchain
from langchain.cache import InMemoryCache
from langchain.chat_models import ChatOpenAI

# Enable global cache
langchain.llm_cache = InMemoryCache()

llm = ChatOpenAI(model="gpt-3.5-turbo")

# First call → API hit
response1 = llm.invoke("What is the capital of France?")

# Second call → Cache hit
response2 = llm.invoke("What is the capital of France?")

print(response1 == response2)  # True
```

---

## 🔹 Redis Cache (Production Distributed)

```python
from langchain.cache import RedisCache
import redis
import langchain

redis_client = redis.Redis(
    host="localhost",
    port=6379,
    db=0
)

langchain.llm_cache = RedisCache(redis_client)
```

---

## 🔹 SQLite Cache (Persistent Local)

```python
from langchain.cache import SQLiteCache
import langchain

langchain.llm_cache = SQLiteCache(
    database_path=".langchain.db"
)
```

---

## 🔎 How Cache Keys Work

Cache is based on:

- Prompt text
- Model name
- Temperature
- Other model parameters

If any change → cache miss.

---

## ❗ Important Notes

- Streaming (`stream()`) is not cached by default.
- You can clear cache via:

  ```python
  langchain.llm_cache = None
  ```

- Redis cache can be cleared with:

  ```python
  redis_client.flushdb()
  ```

# 2️⃣ Rate Limiting & Retries (Resilience)

LLM providers enforce limits:

- Requests per minute
- Tokens per minute

If exceeded → `429 RateLimitError`

We handle this using **`tenacity`** (retry library).

---

## 🎯 Why Retries?

- Temporary failures are common
- Avoid immediate crashes
- Improve UX
- Respect API backoff requirements

---

## 🔹 Basic Retry with Tenacity

```python
from tenacity import (
    retry,
    stop_after_attempt,
    wait_exponential,
    retry_if_exception_type
)

import openai
from langchain.chat_models import ChatOpenAI
from langchain.schema import HumanMessage

@retry(
    stop=stop_after_attempt(5),
    wait=wait_exponential(multiplier=1, min=4, max=10),
    retry=retry_if_exception_type(openai.error.RateLimitError)
)
def call_llm_with_retry(llm, messages):
    return llm.invoke(messages)

llm = ChatOpenAI(model="gpt-3.5-turbo")

response = call_llm_with_retry(
    llm,
    [HumanMessage(content="Tell me a joke")]
)

print(response.content)
```

---

## 🔹 Async Retry (Advanced)

```python
from tenacity import AsyncRetrying, stop_after_attempt, wait_exponential
from langchain.schema.runnable import RunnableLambda

def retry_llm(llm):

    async def ainvoke_with_retry(input):

        async for attempt in AsyncRetrying(
            stop=stop_after_attempt(3),
            wait=wait_exponential()
        ):
            with attempt:
                return await llm.ainvoke(input)

    return RunnableLambda(ainvoke_with_retry)
```

---

## 🔹 Client-Side Rate Limiting

Instead of reacting to limits, prevent exceeding them.

### Using `AsyncLimiter`

```python
from aiolimiter import AsyncLimiter

limiter = AsyncLimiter(max_rate=10, time_period=1)

async def rate_limited_call(chain, input):
    async with limiter:
        return await chain.ainvoke(input)
```

---

## 🔹 Using Semaphore

```python
import asyncio

semaphore = asyncio.Semaphore(5)

async def limited_call(chain, input):
    async with semaphore:
        return await chain.ainvoke(input)
```

# 3️⃣ Cost Tracking (Token Monitoring)

You pay per token.

Without tracking:

- You can't optimize
- You can't budget
- You can't bill customers

LangChain provides **callbacks** to monitor usage.

---

## 🔹 Custom Cost Tracking Callback

```python
from langchain.callbacks.base import BaseCallbackHandler
from langchain.schema import LLMResult

class CostTrackingCallback(BaseCallbackHandler):

    def __init__(self):
        self.total_tokens = 0
        self.total_cost = 0.0
        self.cost_per_1k_tokens = 0.002  # Example

    def on_llm_end(self, response: LLMResult, **kwargs):

        if response.llm_output and "token_usage" in response.llm_output:

            usage = response.llm_output["token_usage"]
            tokens = usage.get("total_tokens", 0)

            self.total_tokens += tokens
            cost = (tokens / 1000) * self.cost_per_1k_tokens
            self.total_cost += cost

            print(
                f"Tokens: {tokens}, "
                f"Total: {self.total_tokens}, "
                f"Cost so far: ${self.total_cost:.4f}"
            )
```

---

## 🔹 Attach Callback to Model

```python
cost_tracker = CostTrackingCallback()

llm = ChatOpenAI(
    model="gpt-3.5-turbo",
    callbacks=[cost_tracker]
)

response = llm.invoke("Hello")

print(cost_tracker.total_cost)
```

---

## 🔹 Attach Callback to Chain

```python
chain = prompt | llm | parser

result = chain.invoke(
    {"topic": "AI"},
    config={"callbacks": [cost_tracker]}
)
```

# 4️⃣ Full Production Example

Combining:

- ✅ SQLite Cache
- ✅ Retry with exponential backoff
- ✅ Cost tracking

```python
import langchain
from langchain.cache import SQLiteCache
from langchain.chat_models import ChatOpenAI
from langchain.callbacks import BaseCallbackHandler
from tenacity import retry, stop_after_attempt, wait_exponential
import openai

# 1. Enable persistent cache
langchain.llm_cache = SQLiteCache(
    database_path="llm_cache.db"
)

# 2. Cost Tracker
class CostTracker(BaseCallbackHandler):

    def __init__(self):
        self.total_cost = 0.0
        self.cost_per_1k = 0.002

    def on_llm_end(self, response, **kwargs):

        if response.llm_output and "token_usage" in response.llm_output:

            tokens = response.llm_output["token_usage"].get(
                "total_tokens", 0
            )

            cost = (tokens / 1000) * self.cost_per_1k
            self.total_cost += cost

            print(
                f"Tokens: {tokens}, "
                f"Cost: ${cost:.4f}, "
                f"Total: ${self.total_cost:.4f}"
            )

cost_tracker = CostTracker()

# 3. Retry wrapper
@retry(
    stop=stop_after_attempt(3),
    wait=wait_exponential(multiplier=1, min=2, max=10)
)
def invoke_with_retry(llm, prompt):

    return llm.invoke(
        prompt,
        config={"callbacks": [cost_tracker]}
    )

# 4. Use
llm = ChatOpenAI(
    model="gpt-3.5-turbo",
    temperature=0
)

response = invoke_with_retry(
    llm,
    "What is the capital of France?"
)

print(response.content)
```

# 🔥 Best Practices

## ✅ Do

- Enable caching in production
- Use persistent cache (Redis/SQLite)
- Add retries with exponential backoff
- Monitor token usage
- Add alerts for high cost
- Limit concurrency to prevent 429 errors

---

## ❌ Avoid

- Calling LLM without retries
- Ignoring token usage
- Running unlimited parallel requests
- Using only in-memory cache in distributed systems
