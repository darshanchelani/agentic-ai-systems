# 2.1 RAG (Retrieval-Augmented Generation)

## 📌 Overview

**Retrieval-Augmented Generation (RAG)** grounds LLM responses in your own data.

Instead of relying only on model training knowledge:

```

User Query
↓
Retrieve Relevant Documents
↓
Inject into Prompt
↓
LLM Generates Grounded Answer

```

---

## 🎯 Why Use RAG?

- ✅ Reduces hallucinations
- ✅ Keeps answers up-to-date
- ✅ Enables QA over private data
- ✅ Supports citations
- ✅ Works with domain-specific corpora

---

# 🏗 RAG Pipeline Architecture

```

1. Load Documents
2. Split into Chunks
3. Generate Embeddings
4. Store in Vector DB
5. Create Retriever
6. Combine Docs + Query
7. Generate Final Answer

```

Each component can be engineered and optimized.

---

# 1️⃣ Document Loaders

Loaders convert raw data → `Document` objects.

Each `Document` contains:

- `page_content`
- `metadata`

---

## 🔹 Why Loaders Matter

- Uniform interface
- Automatic metadata extraction
- Supports 100+ data sources

---

## 🔹 Common Loaders

| Loader                   | Best For           |
| ------------------------ | ------------------ |
| `PyPDFLoader`            | PDFs               |
| `TextLoader`             | Plain text         |
| `CSVLoader`              | Tabular data       |
| `DirectoryLoader`        | Multiple files     |
| `UnstructuredHTMLLoader` | Websites           |
| `ArxivLoader`            | Academic papers    |
| `WikipediaLoader`        | Wikipedia articles |

---

## 🔹 Example: PDF Loader

```python
from langchain.document_loaders import PyPDFLoader

loader = PyPDFLoader("document.pdf")
documents = loader.load()

print(documents[0].page_content[:200])
print(documents[0].metadata)
```

---

## 🔹 Example: Directory Loader

```python
from langchain.document_loaders import DirectoryLoader, TextLoader

loader = DirectoryLoader("./data/", glob="**/*.txt", loader_cls=TextLoader)
docs = loader.load()
```

---

## ⚠️ Pro Tip

Use `lazy_load()` for large datasets to avoid memory overload.

---

# 2️⃣ Text Splitters (Chunking)

Large documents must be split to:

- Fit context window
- Improve retrieval granularity
- Reduce noise

---

## 🔹 Common Splitters

| Splitter                         | Use Case                 |
| -------------------------------- | ------------------------ |
| `RecursiveCharacterTextSplitter` | Default for general text |
| `TokenTextSplitter`              | Precise token control    |
| `MarkdownHeaderTextSplitter`     | Markdown docs            |
| `PythonCodeTextSplitter`         | Code                     |
| `SemanticChunker`                | Semantic-based chunking  |

---

## 🔹 Chunking Strategy

- Chunk size: 500–1500 characters
- Token-based: 200–500 tokens
- Overlap: 10–20%

---

## 🔹 Example: Recursive Split

```python
from langchain.text_splitter import RecursiveCharacterTextSplitter

text_splitter = RecursiveCharacterTextSplitter(
    chunk_size=1000,
    chunk_overlap=200
)

chunks = text_splitter.split_documents(documents)
```

---

## 🔹 Token-Based Split

```python
from langchain.text_splitter import TokenTextSplitter

text_splitter = TokenTextSplitter(
    chunk_size=500,
    chunk_overlap=50,
    encoding_name="cl100k_base"
)

chunks = text_splitter.split_documents(documents)
```

# 3️⃣ Embeddings

Embeddings convert text → dense vectors representing semantic meaning.

---

## 🔹 Embedding Providers

| Provider    | Model                    | Notes                  |
| ----------- | ------------------------ | ---------------------- |
| OpenAI      | `text-embedding-ada-002` | High quality, low cost |
| Cohere      | `embed-english-v3.0`     | Multilingual           |
| HuggingFace | `all-MiniLM-L6-v2`       | Free, local            |
| Local (BGE) | `bge-large-en`           | High performance       |

---

## 🔹 Example

```python
from langchain.embeddings import OpenAIEmbeddings

embeddings = OpenAIEmbeddings()
vectors = embeddings.embed_documents([chunk.page_content for chunk in chunks])
```

---

## 🔹 Caching Embeddings

```python
from langchain.embeddings import CacheBackedEmbeddings
from langchain.storage import LocalFileStore

store = LocalFileStore("./embeddings_cache/")
cached_embedder = CacheBackedEmbeddings.from_bytes_store(
    OpenAIEmbeddings(),
    store
)
```

Reduces recomputation cost during development.

---

# 4️⃣ Vector Stores

Vector stores index embeddings and allow similarity search.

---

## 🔹 Popular Options

| Store    | Best For                     |
| -------- | ---------------------------- |
| FAISS    | Local development            |
| Chroma   | Persistent local             |
| Pinecone | Managed production           |
| Weaviate | Self-hosted hybrid search    |
| Qdrant   | High-performance self-hosted |

---

## 🔹 Example: FAISS

```python
from langchain.vectorstores import FAISS

vectorstore = FAISS.from_documents(chunks, embeddings)
docs = vectorstore.similarity_search("What is RAG?", k=4)
```

---

## 🔹 Save & Load

```python
vectorstore.save_local("faiss_index")
vectorstore = FAISS.load_local("faiss_index", embeddings)
```

---

# 5️⃣ Retrievers

Retrievers wrap vector stores and fetch relevant docs.

---

## 🔹 Basic Retriever

```python
retriever = vectorstore.as_retriever(
    search_type="similarity",
    search_kwargs={"k": 4}
)
```

---

## 🔹 Similarity vs MMR

| Type       | Behavior              |
| ---------- | --------------------- |
| similarity | Top-k most similar    |
| mmr        | Relevance + diversity |

Example:

```python
retriever = vectorstore.as_retriever(
    search_type="mmr",
    search_kwargs={"k": 4, "fetch_k": 20}
)
```

---

## 🔹 Metadata Filtering

```python
retriever = vectorstore.as_retriever(
    search_kwargs={
        "k": 4,
        "filter": {"source": "report.pdf"}
    }
)
```

---

# 6️⃣ Advanced Retrieval Techniques

---

## 🔹 1. Multi-Query Retrieval

Generate multiple queries → merge results.

```python
from langchain.retrievers.multi_query import MultiQueryRetriever

retriever = MultiQueryRetriever.from_llm(
    retriever=vectorstore.as_retriever(),
    llm=llm
)
```

Best for ambiguous questions.

---

## 🔹 2. Parent Document Retrieval

Retrieve small chunks but return larger parent documents.

Improves context quality.

---

## 🔹 3. Self-Query Retrieval

LLM extracts metadata filters from query.

Example:

> “Reports by John from 2022”

Automatically filters:

```
author = John
year = 2022
```

---

## 🔹 4. Contextual Compression

Compress retrieved docs before passing to LLM.

```python
from langchain.retrievers import ContextualCompressionRetriever
```

Saves tokens.

---

## 🔹 5. HyDE (Hypothetical Document Embeddings)

LLM generates hypothetical answer → embed → retrieve.

Useful when query phrasing differs from document phrasing.

---

# 7️⃣ RAG Chain Types

After retrieval, documents must be combined with query.

---

## 🔹 Stuff (Most Common)

All docs → one prompt.

```python
from langchain.chains.combine_documents import create_stuff_documents_chain
```

Best when total tokens fit context window.

---

## 🔹 Refine

Iteratively build answer across documents.

Useful for synthesis tasks.

---

## 🔹 Map-Reduce

Summarize each doc → combine summaries.

Good for large-scale summarization.

---

# 8️⃣ Citations

Essential for trust.

---

## 🔹 Option 1: Prompt Model to Cite

```python
("system", "Answer and cite source name and page number.")
```

---

## 🔹 Option 2: Return Context

```python
result = rag_chain.invoke({"input": "What is RAG?"})

print(result["answer"])
print(result["context"])  # Documents used
```

---

## 🔹 Option 3: Inline Index Markers

Ask model to use `[0]`, `[1]` style references.

Map indices → document metadata.

---

# 🏁 Complete RAG Pipeline Example

```python
# 1. Load
loader = PyPDFLoader("annual_report.pdf")
docs = loader.load()

# 2. Split
text_splitter = RecursiveCharacterTextSplitter(chunk_size=1000, chunk_overlap=200)
chunks = text_splitter.split_documents(docs)

# 3. Embed & Store
embeddings = OpenAIEmbeddings()
vectorstore = Chroma.from_documents(chunks, embeddings)

# 4. Retriever
retriever = vectorstore.as_retriever(search_type="mmr", search_kwargs={"k": 5})

# 5. Prompt
prompt = ChatPromptTemplate.from_messages([
    ("system", "Answer based on context:\n{context}"),
    ("human", "{input}")
])

# 6. Combine
combine_chain = create_stuff_documents_chain(ChatOpenAI(), prompt)

# 7. Create RAG
rag_chain = create_retrieval_chain(retriever, combine_chain)

# 8. Query
response = rag_chain.invoke({"input": "Key financial highlights in 2023?"})
print(response["answer"])
```

# 🧠 Engineering Decisions Cheat Sheet

| Component    | Decision Criteria      |
| ------------ | ---------------------- |
| Loader       | Data source type       |
| Splitter     | Document structure     |
| Embeddings   | Cost vs quality        |
| Vector Store | Scale & persistence    |
| Retriever    | Relevance vs diversity |
| Chain Type   | Context window size    |
| Citations    | Trust requirements     |

---

# 🚀 Key Takeaways

- RAG = Retrieval + Generation
- Good chunking is critical
- Embeddings quality matters
- MMR improves diversity
- Advanced retrieval improves accuracy
- Stuff chain works for most cases
- Always return sources in production

---

# 🔥 Mental Model

RAG is not a single tool.

It is a **modular system** you engineer:

```
Data → Chunks → Vectors → Index → Retrieve → Compose → Answer
```

Mastering RAG means mastering each layer.
